# §8.4 外部对拍记录

日期：2026-08-19　执行：人工浏览器对拍
对象：**ziwei.pub**（iztro 官方 demo，`Powered by iztro`）与 **测测 App**

spec §8.4 要求：「与 ziwei.pub 对拍一批常规中国境内盘，确认裁剪层没丢字段、没改语义。」
本轮用合成测试盘完成（未使用任何真实个人出生数据）。

## 盘一｜2000-08-16 寅时 女（ziwei.pub）

**结果：12/12 宫完全一致。**

主星、辅星、杂耀、亮度、四化、宫干支、大限年龄段、五行局、命主/身主、农历日期全部对上。
裁剪层未丢字段、未改语义。

### 顺带确认的一处 spec 错误

ziwei.pub 显示命宫干支为 **壬午**。spec §7 的示例 JSON 写的是 `"stem": "戊"`，**错**。

早先已按五虎遁独立推出正确值为 `壬`（`(WUHUDUN[庚] + (午−寅)) mod 10`），本轮获得第三方独立佐证。
**spec §7 的示例 JSON 是示意性的，不可当断言基准** —— 断言基准是 `docs/parity-reference.mjs`。

### 需要注意的读图陷阱

ziwei.pub 默认把**运限层叠加**在本命盘上显示。夫妻宫里多出来的 `年解` 是流年年解，
同格还有 `流陀`/`流曲`/`大限·庚`/`流年·丙`。对拍时必须只取本命星，否则会误判为不一致。

## 盘二｜2000-08-16 晚子时 女（ziwei.pub）—— 挖出真问题

初看**所有主星都对不上**，而**所有辅星、杂耀、宫干支、五行局、命主身主全对**。
这个「主星全错 + 其余全对」的模式本身就是 Z2 的指纹：五行局相同、农历日不同。

### 定位

```
我们 dayDivide=current   紫微@酉   父母(酉)=紫微贪狼  福德(戌)=巨门     命宫(申)=天机太阴
我们 dayDivide=forward   紫微@戌   父母(酉)=天机巨门  福德(戌)=紫微天相  命宫(申)=贪狼
ziwei.pub                紫微@戌   父母(酉)=天机巨门  福德(戌)=紫微天相  命宫(申)=贪狼
```

古籍安星诀验算：水二局、农历十七 → 紫微在酉；农历十八 → 紫微在戌。
**ziwei.pub 按农历十八安星，却显示「七月十七」** —— Z2 在参考实现上现场复现。

### 结论：不是算错，是默认约定不同

**ziwei.pub 用 `forward`，本服务默认 `current`。** 晚子时换不换日本来就是两派，两边算法都对。

但这意味着：拿本服务的晚子时盘去和 ziwei.pub 比对，**不传 `dayDivide:'forward'` 就会看到两张完全不同的盘**。

### 由此发现并修复的披露缺口

`forward` 模式下本服务的输出曾经是：

```
lunar:   {"day":17, "timeIndex":12}   ← 出生瞬时的真实农历日，正确
星曜:     按农历十八安放                 ← forward 的定义如此，正确
warnings: []                           ← 线上没有任何说明
```

两边都对，但下游 LLM 无从得知「盘是按次日排的」，唯一线索 `convention.dayDivide`
要求调用方预先知道 `forward` 的含义。这与 `yearDivideNote` 在年轴上解决的是同一个问题。

**已修**：新增 `diagnostics.starPlacementLunarDay`（结构化字段）与 `dayDivideNote`（说明文字），
仅在 `dayDivide:'forward'` **且** `timeIndex === 12` 时出现 —— 与 iztro 自身的触发条件
（`lib/star/location.js`：`timeIndex === 12 && dayDivide !== 'current'`）完全一致，
其他组合下不出现，避免退化成噪音。

## 盘三｜1993-07-14 11:27 北京时 男 昆明（测测 App）

第二个外部实现（非 iztro demo，独立产品），**12/12 宫完全一致**：
主星、辅星、四化、宫干支、大限年龄段、命主/身主、五行局、身宫位置全部对上。
（测测称「交友」，本服务称「仆役」，同宫异名。）

### 流派差异

测测按**北京时间**直接排（其自报「午时」），本服务默认**当地真太阳时**（巳时）。
昆明经度修正 −69.28 分 + 时差方程 −5.79 分，11:27 → 真太阳时 10:11，跨出午时。

本服务把这个选择做成参数（`trueSolar`），测测写死。两种口径都能从本服务取得。

## 总结

| 项 | 结果 |
|---|---|
| 裁剪层保真度 | **通过** —— 两个独立外部实现、三张盘、逐宫全等 |
| spec §7 示例 JSON | **确认有误**（`soulPalace.stem` 应为 `壬` 非 `戊`），已在别处标注 |
| 晚子时默认约定 | ziwei.pub `forward` vs 本服务 `current`，两者皆有据，已记录 |
| 发现的缺陷 | 1 个披露缺口（`forward` 下未声明按次日安星），**已修 + 已测** |

未覆盖：闰月盘、境外出生盘、1900 前后边界盘的外部对拍 —— 这些在外部工具上普遍无法输入
（ziwei.pub 与测测均不收出生地与时区），因此不存在可对拍的外部基准。
